# Modern Tech — функциональная проверка и безопасность

**Статус после исправлений:** см. [результаты и проверки](remediation.md). Ниже сохранён исходный срез аудита; QA-11 при повторной проверке признан ложным выводом.

Дата: 26 ноября 2026. Исходный аудит: локальная рабочая копия develop, localhost:8088, до последующих исправлений.

## Область и доказательства

- Manual: Chrome, администратор — библиотека, фильтры, календарь, сброс, старые версии, вкладка «Данные», облачные диски, команда, журнал и корзина. Пользовательские документы, права и аккаунты при проверке не изменялись.
- Automated: 129 штатных серверных тестов, 1070 assertions; 30 клиентских тестов; клиентский lint и форматирование — проходят.
- Automated: пять отдельных characterization probes, 17 assertions, воспроизводят **ошибочное текущее поведение**. Их успешный результат означает воспроизведение дефекта, а не правильную работу системы. Они находятся вне штатных тестовых suites: `backend/tests/Feature/AuditRegressionTest.php` (после исправлений преобразованы в regression-тесты). Запуск: `docker compose exec -T api php artisan test --filter=AuditRegressionTest`.
- Source: маршруты, политики, проверки файлов, комментарии, сессии, OAuth/облачные передачи, Office callbacks, фронтенд и конфигурации nginx.
- Automated: npm audit и composer audit с обращением к реестрам; пассивные HTTP-запросы без авторизации.
- Файлы `docs/agents/domain.md`, `issue-tracker.md`, `triage-labels.md`, указанные AGENTS.md, отсутствуют. Отчёт не создаёт тикеты и не присваивает отсутствующие статусы трекера. P1/P2 ниже — приоритет исправления аудита.

## QA-01. Отзыв доступа у последнего участника

Шаги: документ с одним выданным разрешением → «Доступ» → меню участника → «Отозвать доступ» → подтвердить. Клиент отправляет `{ "grants": [] }`. Сервер отвечает 422, разрешение остаётся.

Причина: `backend/app/Modules/Documents/Http/Requests/ReplaceDocumentGrantsRequest.php:22`, правило `required` отклоняет пустой массив. Клиент `AccessEditor.tsx` закономерно отправляет пустой список при удалении последнего grant.

Риск: интерфейс обещает отзыв, но доступ фактически сохраняется. Исправление: разрешить присутствующий пустой массив (`present|array`), сохранив авторизацию и ограничения элементов. Проверка: удаление последнего grant успешно, следующий запрос бывшего участника к документу возвращает 404.

## QA-02. Открытая Office-сессия переживает отзыв прав

В README уже явно зафиксировано, что открытое подключение не отзывается немедленно. `ReplaceDocumentGrantsAction` меняет таблицу grants, а `UpdateManagedUserAction` закрывает веб-сессии при блокировке. Ни один путь не отключает пользователя в Document Server. Авторизация `OfficeController::source` защищает новый запрос исходника, но не уже установленное соединение редактора. JWT конфигурации редактора также подписывается без `exp`; срок 8 часов есть только у source capability.

Риск: нельзя обещать немедленное прекращение редактирования/комментирования после отзыва прав или блокировки аккаунта. Исправление: отключение пользователя через поддерживаемый Office command API, согласованная обработка отключения/сохранения и ограниченный срок новых конфигураций. Проверка: два браузерных пользователя, отзыв edit/comment и блокировка аккаунта; открытый редактор теряет возможность изменять файл. Такой двухпользовательский сценарий в этом аудите не выполнялся, поэтому повторный вход по старому JWT не объявляется воспроизведённым взломом.

## QA-03. Потеря изменений списка прав

Шаги: два менеджера открывают один список A+B. Первый удаляет A и сохраняет B. Второй из старой формы добавляет C, отправляя A+B+C. Оба сохранения получают 200; A снова получает доступ. Воспроизведено тестом последовательности устаревших snapshots.

Причина: клиент отправляет весь список, сервер удаляет и создаёт его заново без revision/If-Match: `ReplaceDocumentGrantsAction.php:40`. Блокировка транзакции предотвращает одновременную запись, но не обнаруживает устаревшие данные.

Исправление: optimistic concurrency с ревизией списка прав и 409 либо отдельные операции над одним grant. Проверка: вторая устаревшая запись отклоняется, отозванный grant не появляется снова.

## QA-04. Неучтённые копии черновиков

После Office callback status=2 создаётся новый файл, поле `office_drafts.storage_key` заменяется, предыдущий файл остаётся. Тест подтвердил: старый файл существует, ссылок в office_drafts больше нет, события уборки нет. Источник: `OfficeController.php:183–206`.

`PurgeDocumentAction` собирает текущие storage_key версий и черновиков, поэтому потерянные ссылки не включаются в штатное удаление документа. Это накопление содержимого документов и места на диске; публичный доступ к этим файлам не обнаружен.

Исправление: надёжное задание удаления заменённого файла после commit с проверкой ссылок, а также уборка ранее потерянных копий. Проверка: повторные сохранения и purge на временном хранилище, отсутствие неучтённых файлов; защита от поздних callbacks сохраняется.

## QA-05. Вкладка «Данные» старой версии

Шаги: «Версии» → открыть версию, отличную от текущей → «Данные». В браузере видны «Запрос отклонён» и «Данные не найдены… требуется повторная обработка». Тест подтверждает 404 даже для владельца. Сервер намеренно ограничивает entities текущей опубликованной версией (`DocumentController.php:205–212`), интерфейс предлагает эту вкладку для любой версии.

Исправление: согласовать контракт — либо безопасно поддержать исторические сущности, либо явно скрыть/объяснить недоступность для старой версии. Не выдавать совет о повторной обработке при отказе доступа. Проверка: переходы текущая/старая версия, готовая версия без сущностей, ошибки сети и прав.

## QA-06. Google Drive: неодинаковая обработка 401

Метод `get()` GoogleDisk обновляет отклонённый access token и повторяет запрос. Методы `download()` и `upload()` выполняют прямой запрос, минуя эту логику. При 401 download сразу выбрасывает CloudAuthorizationRequired; тест подтвердил, что переданный refresh callback вообще не вызывается.

Условие: токен был получен при создании provider, но истёк/был отклонён до передачи. Предварительное обновление по expires_at в ProviderFactory снижает вероятность, но не устраняет окно. Реальный Google-аккаунт не подключался.

Исправление: общий механизм авторизации; для загрузки повтор безопасен с очисткой временного файла. Для экспорта повторять только после однозначного отказа авторизации, не после неизвестного результата удалённой записи. Проверка: сначала 401, затем успешный refresh; отозванный refresh_token; timeout после записи без дублирования файла.

## QA-07. Часовой пояс журнала

В браузере публикация версии отображается в истории как 26.11.2026 04:54:50, а соответствующее событие журнала — 26.11.2026 00:54:50. История получает сериализованную Eloquent дату с часовым поясом. Audit API отдаёт raw timestamp из Query Builder; клиент `new Date(e.created_at)` воспринимает строку без offset как местное время (`pages/admin/index.tsx:333`).

Исправление: все API даты — ISO 8601 с Z/offset, единое форматирование клиента, явное соглашение для границ фильтров по датам. Проверка: одно событие в истории и журнале совпадает в UTC и Europe/Ulyanovsk, включая переход суток.

## QA-08. Зависимости

- npm audit: 9 затронутых пакетов, все moderate; корень — minimatch, остальные предупреждения по цепочке ESLint/typescript-eslint. Это инструменты разработки, не девять независимых дыр в клиентском приложении. Advisory: [GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249), исправление minimatch 11.0.1.
- composer audit: 7 advisories в четырёх пакетах: laravel/framework v13.39.0, symfony/http-foundation, http-kernel и routing v8.1.10. Пример: [Laravel concurrency output injection](https://github.com/advisories/GHSA-63hm-g96r-2m2q), исправление 13.40.0. Symfony advisories указывают исправления 8.1.11, например [trusted proxies](https://github.com/symfony/symfony/security/advisories/GHSA-xg2q-4rrq-657q).
- Наличие уязвимой версии подтверждено сканером и lockfile; достижимость всех CVE из маршрутов приложения НЕ доказана. Symfony Security access_control и Laravel Concurrency нельзя автоматически считать используемыми только по наличию транзитивной зависимости.

Исправление: обновить совместимые patch-версии через lockfiles и прогнать серверные/клиентские проверки. Автоматическое обновление зависимостей в этом аудите не выполнялось.

## QA-09. Production Office и API-документация

`compose.production.yaml` выключает development gateway. Production `frontend/nginx.conf` обслуживает статику и api/sanctum/health, но не содержит `/office-editor/` proxy. При сохранении browser_url=/office-editor редактор получает SPA вместо API-скрипта. Аналогично `/docs/api` не направляется в Laravel. В development gateway оба маршрута есть.

Это блокер текущего шаблона выпуска, а не утверждение о сбое уже развёрнутого production. Исправление: отдельная production-конфигурация Office proxy/WebSocket и маршрута документации либо согласованные отдельные URL сервисов. Проверка после сборки production: JS имеет правильный MIME, editor открывается, WebSocket и callbacks работают, документация доступна по ожидаемому адресу.

## QA-10. Защита от встраивания

Пассивная проверка `/` вернула HTML без Content-Security-Policy frame-ancestors и без X-Frame-Options. В nginx-конфигурациях приложения этих ограничений тоже нет. У PDF preview отдельный frame-ancestors self есть, но это не защищает внешнюю страницу приложения.

Риск: интерфейс можно пытаться встроить во фрейм другого сайта для clickjacking. Достижение конкретного привилегированного действия в чужом фрейме не проверялось. Исправление: frame-ancestors self/none в соответствии с нужными интеграциями, согласованная CSP для самого приложения и редактора. Проверка: приложение не встраивается с другого origin, внутренний preview и Office продолжают работать. HTTPS/HSTS на localhost не классифицировались как дефект production.

## QA-11. Регистрация — исправление вывода аудита

Ложное срабатывание: при первоначальном чтении был учтён только маршрут авторизованного пользователя. В App до этого маршрута уже есть отдельная ветка для неавторизованного посетителя, показывающая RegistrationPage по `/register`. Код регистрации исправлять не потребовалось; добавлен клиентский тест. Перенаправление авторизованного пользователя в библиотеку корректно.

## Дополнительные наблюдения, не включённые в подтверждённые уязвимости

- Нет общей квоты диска/числа документов и throttle загрузок: есть ограничение 50 МБ на файл. Нагрузочное истощение не проводилось; до публичной регистрации нужны лимиты ресурсов.
- SavedFilters обрабатывает синтаксически невалидный JSON, но не проверяет тип валидного значения из localStorage. Значения null/объект вместо массива могут сломать открытие меню. Это локальная устойчивость, не удалённая XSS.
- В AccessEditor владельцу всегда рисуются все галочки, даже если роль владельца изменена на observer и серверные права уже ограничены. Проверять эффективные права отдельно от владения.
- В API выдачи участников нет пагинации при запросе без search; AccessEditor всё ещё загружает такой полный список для существующих grants. На большой команде возможны задержки. Замер больших объёмов не выполнялся.

## Что проверено без обнаружения обхода в этом проходе

Штатные тесты проверяют ограничения reader/edit/export и исторических версий, блокировку пользователей, CSRF, OAuth state/PKCE, idempotency, безопасный приём Office callback, форматы/размеры файлов и карантин. Анонимные `/api/v1/me` и `/api/v1/users` вернули 401. `/.env` вернул HTML SPA, а не файл окружения — утечка .env не обнаружена. Ошибочный HTTP 200 для неизвестного SPA пути не является сам по себе раскрытием секрета.

- Реальные OAuth Google/Яндекс, Mail WebDAV, отозванные токены и большие каталоги. Наличие настроек не заменяет реальное согласие провайдера; аккаунты не подключались.
- Production HTTPS, cookies за прокси, заголовки конечного домена, Office и Swagger в production-сборке.
- Полный мобильный/клавиатурный аудит, скринридер, Safari/Firefox, долгие сессии, объёмные документы и нагрузочные пределы.

Полное отсутствие ошибок и уязвимостей не подтверждается ни этим отчётом, ни зелёными тестами. Результат — воспроизводимый список проблем и границы выполненной проверки.
