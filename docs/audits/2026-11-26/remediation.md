Дополнительные замечания отчёта тоже обработаны:

- Проверяется тип и состав JSON сохранённых фильтров, а не только синтаксис.
- Список доступа получает только уже выданные grants/участников; поиск кандидатов остаётся асинхронным. Endpoint ограничивает выдачу.
- Галочки владельца отображают фактические серверные права, включая ограничения неактивного пользователя/наблюдателя.
- Добавлены квоты аккаунта: по умолчанию 1 ГиБ и 1000 версий, включая сохранённые версии. Настраиваются `DOCUMENTS_MAX_ACCOUNT_BYTES` и `DOCUMENTS_MAX_ACCOUNT_VERSIONS`. Для загрузок и облачных передач установлен лимит 30 запросов в минуту. Квота проверяется под блокировкой аккаунта, отказ не оставляет файл/документ. Повторно проверяется право загрузки версии перед записью.

## Границы результата

Реальные OAuth-аккаунты Google/Яндекс/Mail не подключались. Тесты обновления токенов используют изолированные HTTP fakes. Отключение Office интегрировано по официальной [команде drop](https://api.onlyoffice.com/docs/docs-api/additional-api/command-service/drop); фактическое отключение проверено на отдельном временном документе и участнике в Chrome incognito. Серверная операция менеджера выполнена тем же action, который использует API. Одновременное редактирование двумя авторами и отзыв в период активной записи всё ещё требуют отдельного теста. Команда прекращает изменение документа, но уже загруженное содержимое может оставаться доступным для чтения — отзыв прав не удаляет ранее полученные данные с компьютера пользователя.

Production-сборка проверена локально, а не на будущем публичном домене. Конечные HTTPS/cookies/внешние адреса требуют проверки при выборе площадки. Чистый dependency audit не доказывает отсутствие всех возможных уязвимостей приложения.
