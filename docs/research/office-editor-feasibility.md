# Office editor feasibility pointers — 2026-11-07

Scope: read-only exploration for tickets 03–06. Ticket 02 is testing `onlyoffice/documentserver:9.4.0.1` on ARM64. **Nothing below proves a live integration or closes an acceptance criterion.** Current online docs and `master` source can describe features absent from that pinned build; probe the actual build.

## Findings that affect implementation

1. **Do not assume the historical 20-connection cap.** The official 9.4 announcement says Community removed that cap starting with 9.4 and describes a simpler runtime. Community is AGPLv3 with additional terms; no paid connector is needed just to embed the free editor. Check the actual image and installed license response. This removes an old presumed blocker; it does not establish an application resource budget. [Official 9.4 release](https://www.onlyoffice.com/blog/2026/05/onlyoffice-docs-9-4)

2. **ARM64 is supported for Community Docker.** The official guide includes native ARM64 installation, JWT configuration and persistent directories. Its stated resource requirements are vendor guidance, not measurements for our corpus. Keep a separate Compose project, network, private volumes and local-only published ports. [ARM64 guide](https://helpcenter.onlyoffice.com/docs/installation/community/docker/installing/install-arm64), [system requirements](https://helpcenter.onlyoffice.com/docs/installation/community/docker/sys-reqs)

3. **`createConnector()` / Automation API is premium.** The external comments-feed sample explicitly requires Docs Developer plus the extra paid feature. It cannot silently underpin this free solution. In-editor custom plugins are a separate API path. [Automation API](https://api.onlyoffice.com/docs/docs-api/usage-api/automation-api), [paid comments example](https://api.onlyoffice.com/docs/docs-api/samples/automation-api/working-with-comments)

4. **A free custom plugin is a credible starting point.** The official Extended Comments sample uses plugin `executeMethod` calls for AddComment, ChangeComment, GetAllComments, MoveToComment and RemoveComments, with comment events; its declared support is DOCX only. Plugin runtime configuration supports `pluginsData`, autostart and per-plugin options, including an application authorization token. A plugin can call the application's authenticated bridge; this is a proposed architecture, not proof of free external-panel integration. [Extended Comments plugin](https://api.onlyoffice.com/docs/plugins/samples/extended-comments), [plugin runtime configuration](https://api.onlyoffice.com/docs/docs-api/usage-api/config/editor/plugins)

5. **The three format APIs differ.** The current Spreadsheet and Presentation plugin API lists include native comment CRUD and GetAllComments; their published lists omit MoveToComment and comment-change events. The Presentation list does include GoToSlide. DOCX lists MoveToComment and onAddComment/onRemoveComment/onChangeCommentData. GetAllComments was added to spreadsheet/presentation in 8.1. Periodic full comment resynchronization and format-specific navigation may be necessary; do not conclude impossibility from an omitted documentation entry. [DOCX API](https://api.onlyoffice.com/docs/plugins/interacting-with-editors/document-api), [XLSX API](https://api.onlyoffice.com/docs/plugins/interacting-with-editors/spreadsheet-api), [PPTX API](https://api.onlyoffice.com/docs/plugins/interacting-with-editors/presentation-api), [plugin changelog](https://api.onlyoffice.com/docs/plugins/more-information/changelog)

6. **Source confirms a narrower comment envelope.** Current `sdkjs/master` `cell/api_plugins.js` and `slide/api_plugins.js` implement GetAllComments returning Id + converted Data. The XLSX implementation enumerates workbook and per-sheet comments; the PPTX implementation enumerates native document comments. These files do not implement a plugin MoveToComment method. Native `ApiComment` APIs may help resolve position: the PPTX Office API exposes GetPosition; XLSX docs do not expose the same method. Need stable app thread identifiers mapped to native IDs, saved quotes, author identity and tombstones; never recover an anchor by arbitrary matching text. Source copies for inspection are `/tmp/modern-tech-onlyoffice-cell-api_plugins.js` and `/tmp/modern-tech-onlyoffice-slide-api_plugins.js`. [Cell plugin source](https://github.com/ONLYOFFICE/sdkjs/blob/master/cell/api_plugins.js), [slide plugin source](https://github.com/ONLYOFFICE/sdkjs/blob/master/slide/api_plugins.js), [PPTX ApiComment](https://api.onlyoffice.com/docs/office-api/usage-api/presentation-api/ApiComment), [XLSX ApiComment](https://api.onlyoffice.com/docs/office-api/usage-api/spreadsheet-api/ApiComment)

7. **Force-save is asynchronous.** `/command` forcesave accepts a document key and optional userdata correlation identifier. Command success alone is not a saved artifact. Callback status 6 supplies the saved state while editing continues; status 7 is force-save failure. Callback userdata can associate the result with an attempted snapshot; key + application generation + request ID must reject old/duplicate results. Current docs note callback selection can use the most recent tab of a user, so per-tab callback assumptions are unsafe. No documented guarantee atomically joins an unrelated app discussion database transaction to the editor save. A promising probe is to extract native discussions from the same immutable saved OOXML artifact, with explicitly defined app metadata generation; concurrent new changes must remain later draft work. [Force-save command](https://api.onlyoffice.com/docs/docs-api/additional-api/command-service/forcesave), [callback contract](https://api.onlyoffice.com/docs/docs-api/usage-api/callback-handler)

8. **`drop` alone does not prove full access revocation.** The documented command prevents editing while retaining viewing. Current server source `dropUsersFromDocument` publishes a drop event, and `dropUserFromDocument` sends a drop packet to matching connections; it does not forcibly disconnect their sockets. Server source has a separate close-connection mechanism, but it is not the documented public drop command. Source is `/tmp/modern-tech-onlyoffice-DocsCoServer.js` around lines 1590–1650, 4167 and 4797. For ticket 05, prototype an authenticated application proxy that can terminate active WebSockets, deny every subsequent document/resource request, and deny reconnect after ACL generation changes. Test direct socket/file URL bypasses, all tabs, comment-only downgrade, read-only published-context switch and block. Do not present source inspection as proof that a dropped client can still receive later draft changes; measure it. [Drop command](https://api.onlyoffice.com/docs/docs-api/additional-api/command-service/drop), [server source](https://github.com/ONLYOFFICE/server/blob/master/DocService/sources/DocsCoServer.js)

## Next probes after ticket 02 passes

- Run an autostart custom plugin in each pinned editor; enumerate, create, mutate and navigate comments through its free methods. Confirm second-client propagation without reload and full resync after a missed event.
- Insert/delete preceding text, rows and slides; duplicate quotes; move a fragment; delete its last anchor. Record whether native thread IDs survive, whether a deleted anchor also deletes its native comment, and how to retain a single authoritative thread with a tombstone.
- Force-save while another client edits/comments. Store exact downloaded bytes, checksum, native comment extraction, request ID, editor key and app generation. Race a duplicate/late callback and ensure no false confirmed snapshot. Verify callback JWT and URL allowlist independently.
- For seats, use application Redis/DB atomic admission keyed by document + user, with separate tab leases. The editor's global limits and connection counts do not implement the ten-person rule. Then measure authenticated proxy revocation with already-open editors and direct reconnect attempts.
- Only after these live probes pass, measure CPU/RAM/open/save across a fixed corpus and concurrent documents. Ticket 06 must stay open if any essential behavior is unproved.

## Collabora CODE fallback pointers

CODE officially supports ARM64; it is a rolling development edition with no promised production SLA. A September 2026 official forum answer confirms default mode has no document/connection cap, whereas Home Mode imposes 20 connections / 10 documents. Current Collabora SDK describes `Action_RemoveView` and `Reset_Access_Token` via postMessage, but postMessage cooperation is not sufficient proof against a client that ignores it. A 2024 official forum answer warns annotation events were not directly exposed and suggests checking current SDK/source; this is historical, not a present-day impossibility claim. Switching candidates therefore still requires the same actual three-format bridge/snapshot/revocation probes. [CODE product](https://www.collaboraonline.com/code/), [ARM64 support](https://www.collaboraonline.com/blog/arm64-an-officially-supported-platform-for-collabora-online-code/), [2026 limits answer](https://forum.collaboraonline.com/t/does-collabora-code-26-04-2-4-have-any-user-or-concurrent-connection-limits/5023), [SDK manual](https://sdk.collaboraonline.com/25.04/CO-SDK-manual.pdf), [historical annotation discussion](https://forum.collaboraonline.com/t/collabora-online/3164)
