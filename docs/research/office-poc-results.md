## Кандидат и воспроизведение

ONLYOFFICE Docs **Community9.4.0.1**, бесплатный self-hosted образ,
`platform: linux/arm64`. Compose закрепляет multiarch digest:

```text
onlyoffice/documentserver:9.4.0.1@sha256:3ab6ebc7c605e5a32b7ae3ff19daed4925090245acc8100ce2230bd766c88212
ARM64 manifest: sha256:4cf3b55487209b8f53492c545263b7bb257e1be48dba1f9e0b30d2e50371a1c8
```

Команды запуска, проверки, остановки и полный протокол двух клиентов находятся
в [tools/office-poc/README.md](../../tools/office-poc/README.md). Compose содержит
только отдельные harness/documentserver; рабочие PostgreSQL/Redis/файлы не
монтируются. Docker project: `modern-tech-office-poc`, loopback8890/8891.

Среда: macOS ARM64, Docker Engine28.5.1 aarch64,8CPU,7.65GiB Docker memory;
Node24.18.0 на хосте, CPython3.14.7, zlib1.2.12. Существующая платформа продолжает
работать отдельно; её БД и файлы не сбрасывались.

## Продолжение: исполняемый сценарий двух клиентов

Подготовлен `tools/office-poc/acceptance.mjs` с бесплатным автозапускаемым
плагином. Он работает через документированные Office API внутри настоящего
редактора, отдельно проверяет сходимость двух независимых клиентов, видимые
нативные метки курсоров/выделения, свежий callback, файл, закрытие и открытие
под новым key. В конце полного запуска вызывается независимый Python verifier.
Старое содержимое не удовлетворяет уникальным маркерам текущего запуска;
XLSX перед редактированием действительно переводится к10/20 на обоих клиентах.
Старые callbacks исключаются текущим key и временем попытки сохранения.

HTTP-проверка подключения бесплатного плагина показала red на отсутствующей
настройке, затем green. Сейчас проходят3HTTP-теста в изолированном контейнере:
общий ключ/разные личности; отказ поддельного callback; корректные конфигурация
и доставка плагина с тремя поддержанными редакторами. Синтаксические проверки
Node для сервера, плагина и нового сценария проходят.
