# Подключение Яндекс Диска

Пользователь нажимает «Подключить Яндекс Диск», разрешает доступ на странице Яндекса и возвращается в Modern Tech. Приложение проверяет доступ к Диску, создаёт подключение и открывает список файлов. Пользовательский токен вручную не вводится.

## Разовая настройка сервера

1. В [Яндекс OAuth](https://oauth.yandex.ru/client/new/id/) зарегистрируйте приложение типа **«Для авторизации пользователей»**. Тип «Для доступа к API или отладки» с фиксированным адресом `verification_code` не подходит.
2. Выберите веб-платформу и зарегистрируйте адрес возврата. Для стандартного локального стенда это `http://localhost:8088/api/v1/connections/yandex/callback`. Схема, хост, порт и путь должны совпадать с адресом в настройках приложения. Если кабинет не принимает локальный HTTP-адрес, используйте HTTPS-адрес своего окружения и задайте его в конфигурации.
3. Добавьте права `cloud_api:disk.read`, `cloud_api:disk.write`, `cloud_api:disk.info`: чтение для импорта, запись для экспорта и сведения о Диске для проверки подключения и определения аккаунта.
4. В защищённом `backend/.env` задайте `YANDEX_CLIENT_ID`, `YANDEX_CLIENT_SECRET` и `YANDEX_REDIRECT_URI`. Идентификатор и секрет берутся из свойств этого OAuth-приложения. Не вставляйте их в форму облачного подключения и не добавляйте в Git. Пример имён переменных есть в `backend/.env.example`.
5. Если конфигурация Laravel была закеширована, выполните `docker compose exec api php artisan config:clear`. Если значения заданы через окружение контейнера, обновите также соответствующий env-файл Compose и пересоздайте контейнеры, использующие эти значения. Настройки требуются как API, так и обработчику облачных передач для обновления токенов.

Без настроек сервера кнопка подключения недоступна; интерфейс предлагает обратиться к администратору. Для существующих подключений Яндекса можно выбрать «Переподключить». Уже выданные вручную токены продолжают работать, пока провайдер их принимает; после отзыва потребуется вход через Яндекс.

Инструкция провайдера: [регистрация приложения](https://yandex.ru/dev/id/doc/ru/register-auth), [обмен кода и PKCE](https://yandex.ru/dev/id/doc/ru/codes/code-url), [обновление токена](https://yandex.ru/dev/id/doc/ru/tokens/refresh-client).

## Обработка доступа

Код обменивается на токены только на сервере. Одноразовый `state` действует 10 минут, связан с пользователем, его сессией и текущим паролем. Используется PKCE S256. Токены и срок действия хранятся зашифрованными, API подключений не возвращает их браузеру. Возврат пользователя всегда ведёт на фиксированную страницу `/integrations`; коды и токены не переносятся в её URL. Nginx не записывает query-параметры callback в access log.

Истёкший токен обновляется под блокировкой. После ответа 401 один раз повторяется запрос метаданных с обновлённым токеном; загрузка файла в облако вслепую не повторяется. Отозванный refresh-токен переводит подключение в состояние повторной авторизации. Отключение диска во время обновления не восстанавливает удалённые credentials.

## Проверка

Серверные тесты: `docker compose exec api php artisan test --filter=YandexOAuthTest`. Они используют SQLite в памяти и HTTP-заглушки. Проверяются обмен кода, привязка и однократность state, отказ пользователя, проверка Диска, обновление и отзыв токенов, повторное подключение и гонка с отключением.

Для проверки реального аккаунта после настройки сервера: подключите тестовый Диск, откройте каталог, импортируйте небольшой документ, экспортируйте его в отдельную папку, затем отзовите доступ и переподключите Диск. Для выполнения передач должны работать планировщик и `worker-transfers`; импорт также требует обработчиков проверки и извлечения содержимого. Не запускайте старые ожидающие операции без проверки их назначения.
