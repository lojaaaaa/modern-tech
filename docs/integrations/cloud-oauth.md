# Подключение облачных дисков

Настройки размещаются в `backend/.env`; значения секретов не включаются в исходный код.

| Сервис | Переменные | Адрес возврата для локального запуска |
| --- | --- | --- |
| Яндекс Диск | `YANDEX_CLIENT_ID`, `YANDEX_CLIENT_SECRET` | `http://localhost:8088/api/v1/connections/yandex/callback` |
| Google Drive | `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | `http://localhost:8088/api/v1/connections/google/callback` |

При другом домене задайте `YANDEX_REDIRECT_URI` и `GOOGLE_REDIRECT_URI`. Адреса должны точно совпадать с настройками OAuth-приложения.

Для Google включите Drive API и зарегистрируйте OAuth-клиент типа Web application. В режиме тестирования добавьте пользователей в список тестовых аккаунтов. Приложение запрашивает чтение файлов диска (`drive.readonly`) и создание/изменение файлов, доступных приложению (`drive.file`). Для публичного приложения Google может потребовать проверку разрешений.

После изменения окружения очистите кеш конфигурации сервера (`php artisan config:clear`). Откройте «Облачные диски», выберите сервис и «Подключить диск». Вход и согласие выполняются на стороне провайдера. В случае отзыва доступа используйте повторное подключение.

В Google Drive поддерживаются папки и загруженные файлы PDF, DOCX, XLSX и других разрешённых форматов. Нативные документы Google Docs/Sheets/Slides пока не отображаются: для них нужен отдельный конвейер конвертации. При неоднозначных именах папок операция останавливается, чтобы не записать файл в неверную папку.

Коды OAuth одноразовые, состояние связано с пользователем и его сессией, используется PKCE. Токены хранятся зашифрованными; обновление токена сериализовано блокировкой. Тесты проверяют состояние входа и чтение файлов на имитации API. Реальное подключение требует настроенных ключей и согласия владельца аккаунта.
