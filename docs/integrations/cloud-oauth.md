# Подключение облачных дисков

Поддерживаются Google Drive и Облако Mail.ru. Настройки сервера размещаются в `backend/.env`; секреты не включаются в Git.

## Google Drive

Включите Drive API и зарегистрируйте OAuth-клиент типа Web application. Задайте `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` и `GOOGLE_REDIRECT_URI`.

Для локального запуска адрес возврата — `http://localhost:8088/api/v1/connections/google/callback`. В production укажите HTTPS-адрес своего домена. Адрес должен точно совпадать с настройками OAuth-клиента.

В режиме тестирования добавьте пользователей в список тестовых аккаунтов. Приложение запрашивает чтение файлов (`drive.readonly`) и создание/изменение доступных приложению файлов (`drive.file`). Для публичного приложения Google может потребовать проверку разрешений.

После изменения окружения очистите кэш конфигурации (`php artisan config:clear`). Откройте «Облачные диски» → Google Drive → «Подключить диск». Вход и согласие выполняются на стороне Google. При отзыве доступа используйте повторное подключение.

Поддерживаются папки и загруженные файлы разрешённых форматов. Нативные Google Docs/Sheets/Slides не отображаются: сначала экспортируйте их в DOCX/XLSX/PPTX. При неоднозначных именах папок передача останавливается, чтобы избежать записи в неверное место.

Коды OAuth одноразовые, состояние связано с пользователем и сессией, используется PKCE. Токены хранятся зашифрованными; обновление сериализовано блокировкой.

## Облако Mail.ru

В аккаунте Mail.ru создайте отдельный пароль приложения с доступом к Облаку. В разделе «Облачные диски» выберите Облако Mail, нажмите «Подключить диск» и укажите название, почту и пароль приложения. Используется WebDAV через HTTPS. Данные доступа хранятся зашифрованными и доступны только владельцу подключения.

Серверные OAuth-ключи для Mail.ru не требуются. Возможность WebDAV зависит от условий аккаунта у провайдера. При отказе доступа проверьте пароль приложения и доступность WebDAV для аккаунта.

## Проверка

Автоматические тесты проверяют OAuth, права, изоляцию подключений и передачи с имитацией внешних API. Реальное подключение требует настроенного аккаунта и согласия его владельца. После подключения проверьте список файлов, импорт тестового документа и экспорт новой версии в отдельную папку.
