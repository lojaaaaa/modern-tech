# Изменения требований

## Baseline 1.0 - 2026-10-31

Владелец согласовал всю пакетную анкету, полный доступ администратора, импорт и экспорт двух облаков, локальный бесплатный запуск и поручил дальнейшие решения команде. Текущий источник - SPECIFICATION.md; ранние заметки исторические.

Каждое последующее изменение: CR-ID, причина, затронутые FR/NFR/TASK/API/ADR, новая приёмка, влияние на данные/сроки/риски, решение и источник полномочий. Не удалять требование только потому, что тест не прошёл. Рутинные детали реализации разрешены в рамках baseline; изменение пользовательского поведения отражать явно.

## CR-001 - начать реализацию без отдельного compatibility spike

2026-10-31, прямое поручение владельца: пропустить предварительную проверку совместимости, разрабатывать последовательно без промежуточного согласования, сохранить production-quality, линтеры и правила кода. TASK-001 skipped, а не done. TASK-005 больше не зависит от него. Реальные build/test и provider acceptance остаются обязательными. Подключения облаков могут разрабатываться до получения тестовых аккаунтов; live evidence не подменяется mocks.

## CR-002 — предпросмотр и контекстные комментарии, 2026-10-31

Основание: прямой запрос владельца по скриншотам интерфейса. Добавлены preview изображений/PDF и Office→PDF, привязка комментария к выделенному тексту конкретной версии и переход с подсветкой. Яндекс/Mail разделены в UI, убраны избыточные пояснения, улучшены таблицы/адаптация/поиск.

FR-043 уточняется: у комментария необязательны `anchor_start`, `anchor_end` (UTF-16 offsets браузера) и `anchor_quote`; сервер проверяет точное совпадение с текстом указанной версии. Переход из списка открывает эту версию во вкладке «Текст» и выделяет точный фрагмент. Аннотации поверх самого PDF остаются вне текущей реализации: PDF отображается штатным просмотрщиком браузера, текстовое выделение для обсуждения выполняется во вкладке «Текст».

Preview Office генерируется по запросу через processing queue, имеет отдельное состояние в ответе preview API; ошибка конвертации не переводит готовый документ в failed. Постоянная полная state machine preview по исходному ТЗ остаётся частью незавершённого этапа обработки.
