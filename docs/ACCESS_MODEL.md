# Модель доступа

> Обновление 31.10.2026: владелец согласовал пакет решений. Текущая нормативная baseline - [SPECIFICATION.md](SPECIFICATION.md). Ниже сохраняется история исследования; старые открытые вопросы не отменяют принятую спецификацию.

Дата: 2026-10-31. Базовая модель и полный доступ администратора согласованы; остальные детали ниже отмечены отдельно. Источник: U-22 в DISCOVERY.md.

## Подтверждено владельцем

- Администратор управляет системой и автоматически имеет полный доступ ко всем документам. Приватность означает отсутствие доступа у других сотрудников и наблюдателей, но не у администратора.
- Сотрудник может загружать документы.
- Наблюдатель только читает доступные документы.
- На документ отдельно выдаются чтение, комментарии, редактирование и экспорт.
- Новые документы приватны по умолчанию, включая импорт из облака.

## Предлагаемая детализация матрицы

Роль задаёт предел возможностей, ACL — доступ к конкретному документу. Исключение: активный администратор имеет полный доступ без индивидуальной ACL. Наличие ACL не повышает роль. Для заблокированного пользователя все действия запрещены. Отсутствие разрешения означает запрет.

| Действие | Сотрудник | Наблюдатель | Администратор |
|---|---|---|---|
| Загрузить / импортировать новый документ | Да | Нет | Предлагается разрешить |
| Поиск, метаданные, preview, история версий | При read | При read | Да, ко всем документам |
| Добавить комментарий | При read + comment | Нет | Да, ко всем документам |
| Метаданные, сущности, новая версия | При read + edit | Нет | Да, ко всем документам |
| Скачать оригинал / экспортировать в облако | При read + export | Нет, согласно роли «только читает» | Да, ко всем документам |
| Предоставить или отозвать доступ | Предлагается: только владелец документа | Нет | Да, для всех документов |
| Управлять пользователями и ролями | Нет | Нет | Да |
| Диагностика обработки и настройки системы | Нет | Нет | Да |

Связать скачивание оригинала с export предлагается, чтобы оно не обходило ограничение облачного экспорта. Это не DRM: пользователь, которому показано содержимое, может сохранить видимую информацию и сделать скриншот. Нельзя обещать запрет копирования после предоставления чтения.

Предлагается выдавать владельцу сотруднику полный набор прав на созданный документ. Смена его роли на наблюдателя ограничивает действия, даже если старые ACL сохранились. Передача владения, удаление и восстановление требуют отдельных правил. edit само по себе не даёт права раздавать доступ или удалять документ.

При выдаче comment/edit/export интерфейс добавляет read; сервер отклоняет неконсистентную комбинацию. Отзыв read отзывает остальные права. ACL действует на документ и его версии; отдельные ACL версий пока не планируются. Комментарии видны только вместе с документом; политика изменения и удаления собственных комментариев будет описана отдельно.

## Критические проверки для будущего ТЗ

1. Сотрудник A создал документ: сотрудник B и наблюдатель C не видят название, текст, snippets, число совпадений или версии до выдачи доступа.
2. B получил read: может открыть документ, но сервер запрещает комментарий, новую версию и экспорт.
3. B получил comment: может комментировать, но не менять документ.
4. Наблюдателю нельзя выдать эффективные edit/comment/export даже прямым API-запросом.
5. Отзыв доступа действует на следующий серверный запрос, включая download/preview и поиск. Уже показанное содержимое и ранее экспортированная копия не могут быть отозваны задним числом.
6. Ожидающее задание экспорта повторно проверяет роль, ACL и состояние пользователя перед отправкой. Импорт также проверяет право создавать документ и владение подключением.
7. Подмена document_id, version_id или connection_id не позволяет обойти доступ.
8. После выхода/смены пользователя клиентские данные предыдущего пользователя очищаются; серверный кэш не смешивает пользователей и ревизии ACL.
9. Все изменения ролей и ACL отражаются в аудите с актором и временем. Секреты облачных подключений не раскрываются администратору через UI/API.

## Решение об администраторе

Владелец подтвердил автоматический полный доступ администратора ко всем документам. Он действует для поиска, preview, версий, комментариев, редактирования, экспорта и управления ACL. Блокировка аккаунта запрещает действия и администратору. UI приватного документа поясняет: «Доступен вам и администраторам». Полный доступ к документам не раскрывает пароли и токены личных облачных подключений. Действия администратора подлежат тому же аудиту. Проверки должны явно покрывать административное исключение.
