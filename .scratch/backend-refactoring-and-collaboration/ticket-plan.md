# План задач: рефакторинг бэкенда и совместная работа

Status: ready-for-agent

План согласован поручением владельца реализовать его 7 ноября 2026 года: 46 отдельных задач, 254 проверяемых критерия приёмки. Авторитетные задачи опубликованы в `issues/` со статусом `ready-for-agent`. `drafts/` сохраняет исходное предложение. Наличие блокеров учитывается отдельно от статуса.

Источник: [каноническая спецификация](spec.md). Родительская спецификация не изменена. Ни одна задача этим документом не объявляется выполненной.

## Порядок работы

Начальный фронт: **01 и 02**. Это независимые задачи; дальше можно брать любую задачу, все блокеры которой действительно завершены. Номера задают порядок зависимостей, а не обязательную последовательную очередь.

Задача 01 — ограниченный предварительный перенос текущей авторизации, не массовое переписывание. Задачи 02–06 проверяют редактор в изолированном стенде. Задача 06 закрывается только при подтверждённых обязательных возможностях, включая бесплатный мост, согласованный снимок и отзыв открытого доступа. Неуспешный эксперимент не снимает этот блокер. Зависимая реализация начинается после доказанного решения; редактор, версия, таймауты и общий предел нагрузки заранее не выдумываются.

Каждая продуктовая задача проводит один сценарий через нужные данные, API, интерфейс и проверки. Она переносит в новые границы только свой сценарий; протокольные адаптеры и Query не переименовываются механически в Actions. Изменения выполняются на изолированной среде; разрешение на новую схему не означает разрешения сбросить рабочую БД.

В списке приведены только непосредственные блокеры: их зависимости наследуются. Например, задаче 28 не нужно отдельно указывать 06, поскольку путь к ней уже проходит через результаты прототипа.

   - **What it delivers:** Зафиксированный релиз проходит реальные пользовательские сценарии, а принимающий видит результаты проверок, деплоя и независимого review.

## Общие условия приёмки

- Для каждой задачи фиксируются commit, окружение, входные данные и фактический результат. Моки, реальная инфраструктура, браузерная проверка и независимое review отмечаются отдельно.
- Изменённый сценарий использует согласованные термины и владельца данных из пяти модулей. Policies проверяют права, типизированные Actions с одним публичным `handle` выражают мутации, Query отвечает за выборку, адаптер — за внешний протокол. Контроллеры, Jobs и команды остаются входами/доставкой.
- Изменения API сопровождаются OpenAPI и типами клиента в той же задаче. Применимые негативные проверки, аудит, приватность кэша, идемпотентность и обработка ошибок входят в сценарий, не откладываются целиком на финальную приёмку.
- Существующие внешние сценарии сохраняются; совместимость прежних URL/схемы не обязательна. Работа не требует зеркальных unit-тестов каждого Action и не выдаёт SQLite/моки за проверку PostgreSQL/Redis/редактора.
- Каждая логическая реализация проходит через PR по принятому gitflow с применимыми проверками. Задача 46 собирает доказательства и проводит финальную приёмку; создание workflow или PR не считается выполненным deploy/review.
- Временные переходные контракты удаляются в завершающем их сценарии после переноса последнего потребителя. Мёртвые контроллеры, старые обёртки и конкурирующие реализации не остаются как параллельная архитектура.
- Критерии остаются открытыми до фактической проверки. Отсутствующие cloud credentials, reviewer или целевая среда обозначаются явно и не заменяются предположением об успехе.
