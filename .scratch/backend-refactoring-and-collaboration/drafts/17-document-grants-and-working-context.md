# 17: Права документа и разделение черновика с опубликованной версией

Status: needs-triage

Черновик для согласования. Публикация в `issues/` и статус `ready-for-agent` — после утверждения разбиения.

**What to build:** Владелец выдаёт минимальные права, а приложение открывает участнику именно разрешённый контекст — опубликованную версию либо общий рабочий черновик.

**Источник:** [спецификация](../spec.md); истории US-015, US-016, US-038, US-039, US-040, US-041, US-042, US-049, US-104, US-106, US-115, US-124; ID-02, ID-04, ID-05, ID-08, ID-11, ID-12, ID-13, ID-15, ID-16, ID-24, ID-37; TD-02, TD-05, TD-11. US — номер истории в User Stories.

## Критерии приёмки

- [ ] У документа один текущий Working Draft, исходная версия и поколение; неизменяемая версия и производный текст не используются как редактируемое содержимое.
- [ ] Владелец отдельно управляет read/comment/edit/export; дополнительные права требуют read, роль наблюдателя ограничивает эффективные разрешения.
- [ ] Владелец и участники с comment/edit получают черновик в своём режиме; read-only получает опубликованную версию и исторический контекст, без рабочих веток.
- [ ] Контекст проверяется сервером для карточки, вложенных ресурсов и подписки; идентификатор чужого черновика/версии не даёт доступа.
- [ ] Персональные кэши учитывают контекст и разрешения; изменение ACL не выдаёт ранее разрешённый черновик из кэша.
- [ ] UI управления доступом и HTTP-матрица подтверждают роли, приватность, отрицательные запросы и выбор контекста. Остановка уже открытого редактора/каналов завершается задачей 30.

Применяются [общие условия приёмки плана](../ticket-plan.md#общие-условия-приёмки).
