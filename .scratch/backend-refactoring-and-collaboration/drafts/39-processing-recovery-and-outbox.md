# 39: Восстановить обработку документа после остановки очереди или worker

Status: needs-triage

Черновик для согласования. Публикация в `issues/` и статус `ready-for-agent` — после утверждения разбиения.

**What to build:** После перезапуска инфраструктуры документ либо завершает обработку, либо получает объяснимую ошибку, не оставаясь навсегда в промежуточном состоянии.

**Blocked by:** [29: Корректный выпуск при ошибках, повторах и поздних заданиях](29-publication-races-and-failures.md)

**Источник:** [спецификация](../spec.md); истории US-123; ID-03, ID-05, ID-07, ID-21, ID-22, ID-24, ID-47, ID-48; TD-02, TD-06, TD-07, TD-15, TD-16. US — номер истории в User Stories.

## Критерии приёмки

- [ ] Transactional outbox восстанавливает доставку после фиксации состояния и сбоя публикации в очередь; дубли не размножают версии и результаты.
- [ ] Проверены остановки worker между стадиями, timeout внешнего обработчика и повторная доставка; конечный статус и доступная версия определены.
- [ ] Reconciliation возобновляет допустимую работу, не публикует старого кандидата и не маскирует терминальную ошибку бесконечными retry.
- [ ] Команды/Jobs управляют доставкой и вызывают сценарии владельца; бизнес-правила не остаются inline в консольном расписании.
- [ ] Уборка временных/осиротевших результатов не удаляет файл с живыми ссылками версии/снимка; неизвестное состояние не трактуется как разрешение удалить.
- [ ] В реальном Compose с PostgreSQL и Redis показаны остановка, запуск и восстановление; сохранены содержательные сценарии ReconciliationTest.

Применяются [общие условия приёмки плана](../ticket-plan.md#общие-условия-приёмки).
