# 38: Безопасное восстановление облачной передачи с неизвестным исходом

Status: needs-triage

Черновик для согласования. Публикация в `issues/` и статус `ready-for-agent` — после утверждения разбиения.

**What to build:** После таймаута удалённой записи пользователь видит достоверное состояние, а повтор worker не создаёт дубликат или перезапись.

**Blocked by:** [37: Импорт и экспорт через Облако Mail.ru по общему контракту](37-mail-cloud-transfers.md)

**Источник:** [спецификация](../spec.md); истории US-110, US-111, US-123; ID-07, ID-12, ID-38, ID-39, ID-47, ID-48; TD-02, TD-15, TD-16. US — номер истории в User Stories.

## Критерии приёмки

- [ ] Для обоих провайдеров воспроизведён таймаут после возможной записи и потеря ответа; статус не подменяется однозначным успехом/неуспехом без доказательства.
- [ ] Reconciliation использует доступные подтверждения операции/файла; при невозможности определить исход оставляет понятное состояние и явное действие вместо слепого overwrite.
- [ ] Повтор worker, повтор пользователя и конкурирующий обработчик не выполняют вторую необоснованную запись.
- [ ] Перед любой новой попыткой актуально проверяются export, аккаунт и принадлежность подключения; фиксированная версия не меняется.
- [ ] Фоновые повторы имеют конечные таймауты/политику, логи и аудит не содержат секретов; fault-injection проверяет подтверждённый и неопределённый исход.
- [ ] Граница доказательств отмечена: контрактный симулятор ошибок отдельно от реального cloud round-trip.

Применяются [общие условия приёмки плана](../ticket-plan.md#общие-условия-приёмки).
