# 09: Управление ролями и блокировкой пользователей

Status: ready-for-agent

Опубликована после поручения владельца реализовать план 7 ноября 2026 года. Зависимости сохраняются до подтверждённого завершения блокеров.

**What to build:** Администратор изменяет роль или блокирует аккаунт через интерфейс, сохраняя управляемость инсталляции.

**Blocked by:** [08: Безопасный вход, выход и восстановление пароля](08-sessions-and-password-recovery.md)

**Источник:** [спецификация](../spec.md); истории US-009, US-010, US-011; ID-02, ID-05, ID-11, ID-14, ID-48; TD-04, TD-05. US — номер истории в User Stories.

## Критерии приёмки

- [ ] Администратор управляет пользователями, ролями и блокировкой; обычный сотрудник не вызывает эти операции напрямую.
- [ ] Конкурентные блокировки или понижения не устраняют последнего активного администратора; проверка актуального состояния выполняется транзакционно.
- [ ] Изменение роли влияет на последующие HTTP-запросы, включая ограничение наблюдателя; блокировка лишает действующей серверной сессии.
- [ ] Существенное действие попадает в аудит без секретов; API и UI показывают объяснимый конфликт/отказ.
- [ ] Проверены матрица ролей и гонка последнего администратора. Закрытие уже открытых редакторских каналов реализуется задачей 30.

Применяются [общие условия приёмки плана](../ticket-plan.md#общие-условия-приёмки).
