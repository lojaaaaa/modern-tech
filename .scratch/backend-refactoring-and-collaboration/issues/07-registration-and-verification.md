# 07: Саморегистрация сотрудника и подтверждение email

Status: ready-for-agent

Опубликована после поручения владельца реализовать план 7 ноября 2026 года. Зависимости сохраняются до подтверждённого завершения блокеров.

**What to build:** Любой посетитель создаёт аккаунт сотрудника, входит, подтверждает адрес и получает понятный доступ к работе с документами.

**Blocked by:** [06: Закрепить редактор, контракты и измеренный ресурсный бюджет](06-editor-decision-and-resource-budget.md)

**Источник:** [спецификация](../spec.md); истории US-001, US-002, US-003, US-004, US-005, US-006; ID-02, ID-05, ID-07, ID-09, ID-10, ID-11, ID-37, ID-38; TD-01, TD-02, TD-04. US — номер истории в User Stories.

## Критерии приёмки

- [ ] Форма и API создают сотрудника в общей инсталляции; административная роль из входа игнорируется/отклоняется, дубли email корректно обрабатываются.
- [ ] Неподтверждённый пользователь может войти и повторно запросить письмо, видит следующий шаг; загрузка, редактирование и комментирование запрещены на сервере.
- [ ] Проверяются подлинность и срок ссылки, повторное использование, чужой аккаунт и rate limit регистрации/повторной отправки.
- [ ] Локальный сценарий проходит через Mailpit; настройка реальной доставки описана отдельно и не объявляется проверенной без почтового транспорта.
- [ ] Identity владеет сценарием и состоянием; типизированные Actions не принимают HTTP Request. HTTP и браузер проверяют полный путь до подтверждения.

Применяются [общие условия приёмки плана](../ticket-plan.md#общие-условия-приёмки).
