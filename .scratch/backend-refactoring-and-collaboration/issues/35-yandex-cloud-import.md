# 35: Ручной импорт с Яндекс Диска в приватный документ

Status: ready-for-agent

Опубликована после поручения владельца реализовать план 7 ноября 2026 года. Зависимости сохраняются до подтверждённого завершения блокеров.

**What to build:** Пользователь выбирает облачный файл и получает приватный документ с теми же проверками и первым выпуском, что при браузерной загрузке.

**Blocked by:** [11: Первый выпуск с OCR, извлечением текста и индексацией](11-first-publication-processing.md); [34: Личные подключения Яндекс Диска и Облака Mail.ru](34-private-cloud-connections.md)

**Источник:** [спецификация](../spec.md); истории US-109; ID-05, ID-06, ID-08, ID-10, ID-13, ID-17, ID-25, ID-39, ID-46, ID-47; TD-02, TD-05, TD-07, TD-15, TD-16. US — номер истории в User Stories.

## Критерии приёмки

- [ ] UI выбора файла/запуска и состояния передачи проходит через личное подключение пользователя, не доверяя произвольному внешнему URL.
- [ ] Импорт использует общий типизированный вход файла Documents без создания HTTP UploadedFile; антивирус, лимиты и обработка не дублируются и не обходятся.
- [ ] Результат приватен по умолчанию, первый выпуск появляется после успешной обработки; чужой connection ID не работает.
- [ ] Повтор запроса/доставки не создаёт дубликат документа; ошибки получения файла отличаются от ошибки обработки и дают безопасное следующее действие.
- [ ] Контрактный провайдер и реальные ClamAV/Tika/очередь проверяют путь до готовой версии; реальный cloud round-trip записывается отдельно при наличии доступа.

Применяются [общие условия приёмки плана](../ticket-plan.md#общие-условия-приёмки).
