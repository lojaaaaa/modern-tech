# 01: Перенести текущую авторизацию документов в Policies

Status: ready-for-human

Implementation: complete

Опубликована после поручения владельца реализовать план 7 ноября 2026 года. Зависимости сохраняются до подтверждённого завершения блокеров.

**What to build:** Текущие операции с документом продолжают работать с едиными проверками доступа; существующие ограничения выдачи и приватность сохраняются при устранении отдельной обёртки Access.

**Blocked by:** Нет — можно начинать сразу после согласования плана.

**Источник:** [спецификация](../spec.md); истории US-015, US-016, US-031, US-037, US-049, US-114, US-115; ID-02, ID-04, ID-06, ID-07, ID-13; TD-02, TD-03, TD-05, TD-16. US — номер истории в User Stories.

## Критерии приёмки

- [x] Проверки одного документа используют Policies владельца сущности; SQL-ограничение видимости остаётся частью Query и применяется до count, пагинации и фрагментов.
- [x] Матрица действующих ролей проходит для карточки, preview, скачивания и вложенных ресурсов; идентификатор чужой версии не подменяет проверку принадлежности.
- [x] Удалена заменённая обёртка Access после переноса всех её потребителей; нет универсального Service/Action для всех действий.
- [x] Сохранены текущие пользовательские результаты и API-проверки приватности; новые правила публикации будут введены отдельно, без административного обхода.
- [ ] Изменение проходит имеющиеся проверки в отдельном PR; не требует сброса рабочей БД или одновременного переписывания остальных модулей.

Применяются [общие условия приёмки плана](../ticket-plan.md#общие-условия-приёмки).

## Comments

7 ноября 2026 года. Реализовано в ветке `implement/01-document-policies`, основанной на интеграционной ветке, baseline `9a7c9c8`. Реализация: `backend/app/Modules/Documents/Policies/DocumentPolicy.php`, регистрация через Laravel Gate, перенесены контроллеры, ресурс документа и повторная авторизация инициатора облачного экспорта в worker. SQL-видимость и поисковые Query не изменены; схема и рабочая БД не изменялись. В Policy отсутствуют глобальный административный `before` и способность публикации: эта задача не вводит новые правила выпуска.

Согласованные точки проверки — существующие HTTP API документов, версий и комментариев (TD-02/03/05/16), а также сохранённые проверки очереди экспорта. `DocumentPolicyApiTest` содержит 11 вариантов матрицы ролей и проверки принадлежности чужой версии и приватности count/пагинации. Проверяются содержимое preview/скачивания, результат изменения названия, отправленный комментарий и эффективные права; тесты не привязаны к приватным методам Policy.

Проверки выполнялись локально на PHP 8.5.8, зависимости из существующего `composer.lock`; SQLite `:memory:`, отдельное тестовое хранилище `Storage::fake`, временный тестовый APP_KEY. Рабочие БД и файлы не использовались. Сначала API-матрица прошла на прежней реализации, затем после удаления Access получен RED (500 вместо 200 из-за оставшегося потребителя); перенос на Gate вернул GREEN.
