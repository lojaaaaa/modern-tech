# 34: Личные подключения Яндекс Диска и Облака Mail.ru

Status: ready-for-agent

Опубликована после поручения владельца реализовать план 7 ноября 2026 года. Зависимости сохраняются до подтверждённого завершения блокеров.

**What to build:** Пользователь управляет своими облачными подключениями, а чужие пользователи и администраторы не получают его секреты.

**Blocked by:** [08: Безопасный вход, выход и восстановление пароля](08-sessions-and-password-recovery.md)

**Источник:** [спецификация](../spec.md); истории US-050; ID-02, ID-05, ID-06, ID-08, ID-13, ID-37, ID-38, ID-46, ID-48; TD-02, TD-05, TD-15, TD-16. US — номер истории в User Stories.

## Критерии приёмки

- [ ] Создание, проверка состояния и удаление личного подключения доступны в UI и API для обоих сохранённых провайдеров.
- [ ] Секреты шифруются при хранении, не возвращаются через list/detail/error и не пишутся в логи/audit; административный доступ к документу не открывает чужое подключение.
- [ ] Проверяется принадлежность подключения текущему пользователю для каждого вызова, включая постановку передачи в очередь.
- [ ] Integrations владеет подключением, провайдеры остаются адаптерами протокола; HTTP-детали не проникают в общий сценарий передачи.
- [ ] Контрактные проверки покрывают приватность и ошибки авторизации провайдеров; реальное подключение помечается отдельно и требует доступных учётных данных.

Применяются [общие условия приёмки плана](../ticket-plan.md#общие-условия-приёмки).
