# 29: Корректный выпуск при ошибках, повторах и поздних заданиях

Status: ready-for-agent

Опубликована после поручения владельца реализовать план 7 ноября 2026 года. Зависимости сохраняются до подтверждённого завершения блокеров.

**What to build:** Сбой нового выпуска или запоздалый результат не лишает читателей прежней версии и не делает старое содержимое актуальным.

**Blocked by:** [28: Выпуск владельцем подтверждённого файла и снимка обсуждений](28-publish-confirmed-snapshot.md)

**Источник:** [спецификация](../spec.md); истории US-080, US-081, US-082, US-083, US-084, US-085; ID-07, ID-19, ID-20, ID-21, ID-22, ID-24, ID-36, ID-39, ID-47; TD-02, TD-06, TD-07, TD-11, TD-12. US — номер истории в User Stories.

## Критерии приёмки

- [ ] Ошибка сканирования/извлечения/индексации нового кандидата сохраняет прежнюю опубликованную версию; UI показывает причину и состояние кандидата.
- [ ] Перестановка завершения двух выпусков и поздний callback не делают старую версию текущей; проверено реальное конкурентное изменение в PostgreSQL.
- [ ] Повтор одного запроса/задания не создаёт второй выпуск; иной payload с тем же ключом даёт конфликт.
- [ ] Изменения после границы снимка остаются неопубликованными независимо от завершения фонового задания.
- [ ] Поиск и preview переключаются только на готовое нужное состояние, без смешения нового индекса со старым файлом/обсуждениями.
- [ ] Управляемые отказы и повторная доставка воспроизводятся через API/реальную очередь; наличие HTTP 202 само по себе не считается успешным выпуском.

Применяются [общие условия приёмки плана](../ticket-plan.md#общие-условия-приёмки).
