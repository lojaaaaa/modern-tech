**What to build:** Пользователь управляет своей серверной сессией и паролем, а после выхода следующий аккаунт не получает данные предыдущего.

**Blocked by:** [07: Саморегистрация сотрудника и подтверждение email](07-registration-and-verification.md)

**Источник:** [спецификация](../spec.md); истории US-007, US-008, US-012, US-124; ID-10, ID-11, ID-37, ID-38, ID-39; TD-04, TD-13, TD-16. US — номер истории в User Stories.

## Критерии приёмки

- [ ] Сохранены cookie-сессии, CSRF, защита входа по частоте и корректное обновление сессии; неверные данные не раскрывают чужие сведения.
- [x] Запрос и завершение сброса пароля проверяются через письмо, включая срок и повтор ссылки; поведение прежних сессий явно закреплено.
- [ ] Logout очищает серверную сессию, клиентский query-cache, состояние документа и подключения; смена аккаунта не восстанавливает прежний приватный экран.
- [ ] Неподтверждённый и заблокированный аккаунты получают соответствующие разрешённые состояния, без обхода проверки через старый клиентский кэш.
- [ ] HTTP и два последовательных браузерных входа подтверждают отсутствие утечки; существующие проверки сессии сохранены.

Применяются [общие условия приёмки плана](../ticket-plan.md#общие-условия-приёмки).

## Comments

### 2026-11-08 — реализация и фактическая проверка

Сохранены web cookie/CSRF и ротация сессии; вход вынесен в типизированный Action,
email нормализуется, пять ошибок за минуту на email/IP дают 429 с Retry-After.
Для неверных данных и заблокированного аккаунта используется одинаковая ошибка.
Password broker обёрнут в транзакцию с блокировкой пользователя до проверки и
потребления токена. Ссылка действует 60 минут, повтор отвергается; после сброса
database-сессии удаляются, а auth.session дополнительно проверяет хеш пароля.
Письмо восстановления отправляется после commit в short, как письмо подтверждения.

Клиент очищает приватные queries/mutations при смене сессии и фоновом /me→401,
прерывает запросы прежнего аккаунта и отбрасывает их запоздалые ответы. Приватное
поддерево UI перемонтируется по ID аккаунта. API JSON запрещает сохранение в кэш.
OpenAPI и клиентские типы перегенерированы из Scramble.

Критический HTTP-набор SessionRecoveryTest: 6 тестов / 42 assertions прошли.
Application: 4 компонентных теста прошли, включая фоновое истечение и запоздалый
ответ /me после logout. Это публичные HTTP/UI seams; отдельных зеркальных
Action-тестов не добавлено. Форматирование и frontend lint прошли.

Браузерный сценарий tools/app-e2e/session.mjs подготовлен, но запуск Chrome в
sandbox завершился до выполнения сценария. Настоящая SMTP-доставка reset-письма,
два браузерных входа с приватным документом и независимые старые cookie в задаче
08 пока не подтверждены. Существующий Smoke/session.php сохранён, в этой задаче
повторно не запускался. PostgreSQL-конкурентное потребление reset-токена отдельно
не проверялось. Критерии с этими доказательствами сознательно не отмечены пройденными.
Дальнейшие браузерные проверки и широкие повторные прогоны остановлены по прямому
поручению владельца: приоритет реализации и перехода к задаче 09. Внешнее ревью
отменено владельцем; публикации и push в GitLab запрещены.
