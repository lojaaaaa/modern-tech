# Изолированный прототип мест редактора

Это исследовательский стенд задачи [05](../../.scratch/backend-refactoring-and-collaboration/issues/05-poc-seats-and-revocation.md), не часть приложения. Он моделирует документ, тестовые учётные записи, права и соединения, используя отдельный Redis и опциональный экземпляр ONLYOFFICE. Данные основного приложения, существующий PoC редактора и их контейнеры не используются. На хост публикуется только `127.0.0.1:8894`; Redis и редактор доступны только внутри отдельной сети Compose.

## Запуск и проверка

Требуется Docker Compose и локально доступные образы `redis:7.4-alpine`, `node:24-alpine` (в compose закреплён digest Node). Из этого каталога:

```sh
docker compose up -d
docker compose exec -T gateway node --test test.mjs
```

Для опытов с настоящим редактором сначала соберите локальный образ из `tools/office-poc/documentserver-patch` по инструкции соседнего прототипа, затем выполните `docker compose --profile editor up -d`. Откройте `http://localhost:8894/` и создайте сессию через форму; каждую новую вкладку запускайте через форму отдельно. Альтернативно `POST /session` возвращает `editorUrl`, который надо открыть в браузере. Редактор запускается через шлюз; прямой порт Document Server не публикуется. Этот режим работает только с прилагаемым синтетическим DOCX. Переменная `POC_PORT` меняет порт на хосте для изолированного запуска.

Каждая сессия использует собственный случайный поддомен `*.localhost` и host-only HttpOnly cookie. Код запуска передаётся во фрагменте URL, удаляется со страницы до POST и принимается один раз только на назначенном origin; cookie нельзя использовать с другим именем узла. Для работы браузер должен разрешать поддомены localhost в loopback. Это локальный механизм демонстрационного стенда, не готовая схема аутентификации продукта.

Проверка создаёт отдельные тестовые документы, использует HTTP и настоящий Redis: девять пользователей и вторая вкладка, одновременная гонка за десятое место, повтор после закрытия обеих вкладок, прекращение открытого тестового потока и переход на права опубликованной версии. Вторая проверка охватывает независимость edit/comment и блокировку. Это не испытание десяти браузеров или редактора. Запущенный стенд останавливается `docker compose stop`.

Для ручных экспериментов запрос `POST /session` с JSON `{"doc":"doc1","user":"alice","password":"local-demo-only"}` выдаёт токен и режим `edit`, `comment` или `view`. Токен передаётся как `Authorization: Bearer …`; `POST /seat` повторяет попытку занять место, `POST /heartbeat` продлевает сессию, `POST /close` завершает её. Пример данных черновика — `GET /draft`, пример долгого потока — `GET /draft/stream`, опубликованной версии — `GET /published`. Изменение демонстрационных прав — `POST /admin/permissions` с JSON `{"secret":"local-demo-only","doc":"doc1","user":"alice","read":true,"comment":true,"edit":false,"blocked":false}`. Смена прав закрывает текущие тестовые соединения и инвалидирует все токены пользователя для документа; новая сессия получает текущие права. Read без edit/comment открывает только опубликованную версию. Значение `POC_SECRET` можно задать окружением Compose; пароль и механизм выдачи идентичности исключительно демонстрационные, это не аутентификация платформы.

## Модель и границы

Один Lua-вызов Redis считает **разных пользователей** документа и атомарно выдаёт место либо оставляет доступный режим comment/view. Вторая вкладка записывается отдельным connection ID, но место остаётся одним; release и heartbeat проверяют идентичность соединения в Redis. Все ключи документа используют один hash tag. Heartbeat использует время Redis и не продлевает уже истёкшее соединение. На шлюзе также действует таймер бездействия (по умолчанию 30 секунд, `LEASE_MS`): он сначала инвалидирует токен и закрывает контролируемые потоки, затем освобождает место. Таймер не является измеренной задержкой для реального редактора.

**Истёкшая запись никогда не освобождается одним лишь истечением срока Redis.** Если шлюз или Redis вышел из строя прежде чем произошло освобождение, запись может остаться и блокировать место. Это намеренный отказ с сохранением запрета: неизвестно, продолжает ли другой процесс передавать черновик. Автоматического восстановления таких записей и распределённой координации нет. Стенд рассчитан на **один экземпляр** шлюза; несколько экземпляров или ручное удаление Redis-ключей при работающих старых сессиях небезопасны. Для чистого повторного запуска остановите весь этот отдельный Compose-проект, убедитесь, что старый шлюз остановлен, затем удалите **только его** volume `modern-tech-office-seats-poc_seats-redis` и запустите проект снова. Права и сессии хранятся в памяти процесса и после перезапуска не сохраняются.

Шлюз выдаёт конфигурацию с JWT, проксирует HTTP и WebSocket к отдельному Document Server и при инвалидировании сессии закрывает отслеживаемые соединения; новые запросы проверяют права. В одном браузерном опыте DOCX загрузил `Editor.bin` через шлюз, а после отзыва доступа `/office-config` вернул 401. Это не доказывает прекращение передачи по уже открытому WebSocket, безопасность всех возможных маршрутов редактора или отзыв уже выданного editor JWT. Не используйте этот демонстрационный шлюз в продукте как границу безопасности: проксирование и capability URL ещё требуют проверки и ограничения. Команда ONLYOFFICE `drop` отключает редактирование, сохраняя просмотр; она не является полным отзывом чтения.

Стенд сохраняет DOCX отдельного документа после подписанного JWT callback со статусом 2: URL должен указывать на `/cache/` внутреннего Document Server или на зарегистрированный localhost-origin сессии этого документа; скачивание выполняется только с внутреннего Document Server. Архив проверяется по структуре, длине и CRC, затем атомарно заменяет файл документа в отдельном томе `office-files`. После успешного сохранения или callback 4 старый ключ закрывается, новая конфигурация получает новый. Исходный fixture используется только до первого сохранения. Чтобы не открыть устаревший файл, пока закрытый редактор ещё не вернул callback, шлюз временно отказывает в новой конфигурации. У каждого URL источника отдельная случайная capability, которая не является токеном API и отзывается вместе с сессией.

В отдельном Compose-стенде реальный редактор изменил DOCX; callback сохранил 40344 байта, новая конфигурация выдала новый ключ, source вернул сохранённый DOCX. Независимая проверка `zipfile.testzip()` прошла и нашла добавленный маркер в `word/document.xml`. Само повторное открытие сохранённого файла в UI редактора этим сценарием не проверялось. Критическая HTTP-проверка отвергает поддельную подпись, чужой origin и повреждённый DOCX, проверяет изоляцию двух документов и отзыв source capability.

Это опыт сохранения файла, а не подтверждённый снимок с обсуждениями: порядок и повторение callback, восстановление после сбоя и смены процесса, доставка событий, одновременное открытие при повторном запуске, долгосрочная целостность и публикация не доказаны. Ключи открытых редакторов находятся в памяти шлюза; после аварийного перезапуска процесс не восстанавливает их и не координируется со старыми редакторами. Для безопасного ручного опыта сначала остановите все редакторы этого стенда и только затем перезапускайте шлюз. Force-save со статусом 6 намеренно отклоняется: порядок нескольких сохранений ещё не установлен. Поддерживаются обычные незашифрованные DOCX-архивы без ZIP64; непроверенный архив не заменяет предыдущий файл.

Проверены две реальные вкладки одного аккаунта в одном браузерном контексте: обе загрузили Editor.bin на разных origin, после закрытия одной запрос конфигурации второй вернул 200. Если мест нет, в панели есть кнопка повторной попытки; при получении места шлюз выдаёт новую подписанную конфигурацию, а страница заменяет редактор и сообщает об успехе после события готовности. В изолированном испытании 10 тестовых сессий заняли места, одиннадцатый пользователь увидел отказ при повторе, после освобождения места получил конфигурацию `edit=true` и открыл редактор; отзыв доступа закрыл его iframe. Cookie-запросы изменения состояния дополнительно требуют точного origin сессии: соседний localhost-origin не может занять место или закрыть чужую сессию.

Обычная перезагрузка страницы сохраняет ту же сессию, пока её lease ещё действует. Событие `pagehide` само по себе не освобождает место: браузер не позволяет надёжно отличить закрытие вкладки от перезагрузки. Явная кнопка «Закрыть» завершает сессию сразу; при неявном закрытии шлюз завершает потоки и освобождает место после истечения lease при доступном Redis. После отказа шлюза или Redis безопасное автоматическое освобождение не гарантируется. Переключение в edit перезапускает редактор; сохранение вводимых в этот момент замечаний и восстановление пропущенных изменений отдельно не доказаны. Не проверены совместное редактирование в этих вкладках, 10/11 реальных браузеров, переподключение после истечения lease, все маршруты отзыва и фактические задержки. Задача 02 остаётся блокером; задача 05 остаётся открытой.
