# Telegram Business: проверка временных медиа

Целевая первая версия описана в [SPEC.md](SPEC.md), согласована 9 ноября 2026 года.
Ход интервью и исследования — в [PRODUCT-DISCOVERY.md](PRODUCT-DISCOVERY.md).
Дизайн — [DESIGN.md](DESIGN.md), тексты — [COPY.md](COPY.md),
новое исследование качества дизайна и текста — [research/README.md](research/README.md).
Эта инструкция относится к экспериментальному приёмнику: готового Mini App
и полной реализации спецификации в нём пока нет.

Экспериментальный локальный приёмник, Python 3.10+, без зависимостей.
Главная цель — выяснить, отдаёт ли Bot API одноразовые фото/видео и медиа
с таймером через бизнес-подключение. В живом тесте одно из фото стало доступно
через `reply_to_message` после ответа на него: скачан JPEG 960×1280.
Другой ответ содержал только метаданные без файла. Это частичный результат:
автоматическое получение всех временных медиа, видео и сохранение после
исчезновения оригинала пока **не подтверждены**.
Если Telegram не передаёт файл боту, этот прототип не обходит ограничение.

## Запуск

1. Создай отдельного бота через @BotFather. В его настройках включи Secretary Mode (ранее Business Mode).
2. В своём Telegram открой настройки Telegram Business / чат-ботов,
   подключи созданного бота и разреши ему только тестовый чат с согласным участником.
   Для эксперимента не нужны разрешения на подарки, Stars, профиль или истории.
3. Узнай числовые Telegram ID своего аккаунта и тестового собеседника.
   Username и номер телефона не подходят.
4. Запусти из корня репозитория:

   ```sh
   python3 tools/telegram-media-probe/probe.py
   ```

Токен вводится скрыто, затем программа запросит два ID.
Можно передать TELEGRAM_BOT_TOKEN, TELEGRAM_OWNER_ID и TELEGRAM_CHAT_ID
через окружение или файл `.env` рядом с программой (формат `KEY=value`, без кавычек).
Значения окружения имеют приоритет над `.env`.
Токен вводи локально, не отправляй его в переписку.

Работает один процесс на одного тестового бота. Существующий webhook программа
не удаляет и при его наличии прекращает запуск.

## Проверка главного требования

Сначала отправь обычное небольшое фото и убедись, что вывод содержит `result=saved`.
Затем по отдельности отправь фото и видео для одного просмотра, фото и видео
с таймером. Для каждого случая проверь файл до открытия, после открытия
и после исчезновения сообщения в Telegram. Отдельно проверь текст с автоудалением.
Используй разные тестовые картинки для каждого случая.

Если прямое событие не пришло, ответь текстом на ещё не открытое временное
медиа в том же чате. Прототип также пытается скачать медиа из
`reply_to_message`. Открывать оригинал для этого эксперимента не требуется.

В `data/archive.sqlite3` сохраняются исходные события только выбранного чата
подтверждённого владельца, версии изменений и уведомления об удалении.
В таблице `files` находятся пути сохранённых файлов, ошибки и число попыток.
Файлы лежат рядом с базой с расширением `.bin`: их можно открыть подходящим
просмотрщиком или скопировать с расширением `.jpg` / `.mp4`.

Для просмотра результатов скачивания:

```sh
sqlite3 tools/telegram-media-probe/data/archive.sqlite3 \
  'SELECT update_id,kind,path,error,attempts FROM files ORDER BY update_id;'
```

Успех для временного медиа — получена полная открывающаяся копия именно
тестового файла, которая остаётся после исчезновения оригинала. Сохранённый
JSON, миниатюра или обычное фото не подтверждают поддержку одноразовых медиа.
Если файл не появляется, изучи payload события: наличие недоступного медиа
или отсутствие события — тоже результат эксперимента, а не успех.

## Просмотр в Telegram

Открой своего бота и отправь `/start`: появится кнопка «Сохранённые фото».
Кнопка и команда `/photos` отправляют последние 5 скачанных фото из локального
архива. Доступ разрешён только владельцу (TELEGRAM_OWNER_ID) в личном чате
с ботом. Фото повторно загружаются в Telegram, создавая отдельные сообщения.
Видео и более старые записи пока доступны только в локальном архиве.

## Границы прототипа

- Основной архив локальный; в Telegram доступен просмотр последних фото,
  без автоматических уведомлений или ИИ.
- Первое скачивание выполняется сразу после записи события; до трёх попыток.
  Курсор сохраняется вместе с событием, повторные события не создают дубликаты.
- Скачивания последовательные: большой поток может задержать обработку медиа.
- Лимит прототипа — 20 MiB на файл. Большие видео пока не поддерживаются.
- Уже исчезнувшие до получения ботом сообщения не восстанавливаются.
- Отключение бизнес-бота останавливает новые приёмы, но не стирает локальные копии.
- Архив содержит переписку в открытом виде, без шифрования и автоочистки.
  `data/` исключён из Git; права новых файлов ограничены текущим пользователем.
  Для удаления архива останови процесс и удали каталог `data/`.
- Реальный тест требует твоего подключения и отправки тестовых сообщений;
  проверка с подставным API подтверждает только работу локального приёмника.
