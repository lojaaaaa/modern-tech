# Личный Telegram-архив

Локальный приёмник Telegram Business и Mini App для одного владельца.
В архиве видны изменения и удаления сообщений обеих сторон, история полученных
правок и фото, сохранённые после ответа владельца. Обычная переписка целиком
в интерфейсе не показывается. Python 3.10+, стандартная библиотека; отдельной
сборки фронтенда и установки Python-пакетов нет.

Требования: [SPEC.md](SPEC.md). Интерфейс: [DESIGN.md](DESIGN.md), строки:
[COPY.md](COPY.md). Наблюдения за временными медиа — в [PRODUCT-DISCOVERY.md](PRODUCT-DISCOVERY.md).
Фактические проверки и незавершённые условия выпуска — в
[приёмке](../../.scratch/telegram-archive/acceptance.md).

## Настройка

1. Создай бота в @BotFather и включи Secretary Mode (ранее Business Mode).
2. Подключи его к своему аккаунту в настройках Telegram Business / чат-ботов
   и разреши нужные диалоги. Для первого опыта удобно выбрать один тестовый чат.
3. Укажи токен и свой числовой Telegram ID в `tools/telegram-media-probe/.env`
   по образцу [.env.example](.env.example). Username и телефон вместо ID не подходят.
   Токен вводится только локально и остаётся на сервере.
4. Для открытия Mini App укажи `TELEGRAM_WEBAPP_URL`: доступный HTTPS-адрес,
   направленный через твой туннель или reverse proxy на локальный HTTP-сервер.
   Настройка адреса и постоянного сервера не выполняется автоматически.

Формат `.env` — `KEY=value`, без кавычек. Переменные окружения имеют приоритет.
Файл читается явно при запуске CLI; импорт модулей в тестах его не загружает.

| Переменная | Значение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Токен бота; нужен обоим процессам |
| `TELEGRAM_OWNER_ID` | Положительный числовой ID владельца; нужен обоим процессам |
| `TELEGRAM_CHAT_ID` | Пусто — все разрешённые личные бизнес-диалоги; положительный ID — тестовый диалог; `0` — обнаружение ID без сбора переписки |
| `TELEGRAM_DATA_DIR` | Общий каталог обоих процессов; по умолчанию `data/` рядом с программами. Для своего каталога удобно указать абсолютный путь |
| `TELEGRAM_WEBAPP_URL` | Необязательный HTTPS-адрес без логина и пароля в URL; без него кнопки открытия у бота нет |
| `TELEGRAM_HOST` | Адрес HTTP-сервера, по умолчанию `127.0.0.1` |
| `TELEGRAM_PORT` | Порт HTTP-сервера, по умолчанию `8787` |

Если раньше был задан тестовый `TELEGRAM_CHAT_ID`, очисти его значение для сбора
всех разрешённых диалогов. Собственные исключения настраиваются в Mini App.

## Запуск

Из корня репозитория запусти сервер интерфейса:

```sh
python3 tools/telegram-media-probe/server.py
```

В другом терминале запусти приёмник:

```sh
python3 tools/telegram-media-probe/probe.py
```

У обоих процессов должны совпадать владелец, токен и каталог данных.
Приёмник может запросить отсутствующие токен и ID локально; для HTTP-сервера
их нужно заранее задать в окружении или `.env`. Запускай один приёмник на бота.
Существующий webhook приёмник не удаляет: при его наличии запуск прекращается.
Для остановки каждого процесса нажми `Ctrl+C` в его терминале.

Отправь `/start` в личный чат с ботом. При заданном HTTPS-адресе появится кнопка
«Открыть архив». Уведомления открывают нужный диалог. `/photos` отправляет последние
пять сохранённых фото; `/notifications` показывает настройки. Типы уведомлений
переключаются командами `/edits_on`, `/edits_off`, `/deletes_on`, `/deletes_off`.
Команды доступны только владельцу в его личном чате с ботом.

Прямое открытие локального адреса в обычном браузере показывает оболочку,
но не даёт доступа к архиву. Все API-запросы, включая фото, аватары, прочтение,
настройки и удаление, требуют проверенных сервером данных запуска Telegram.
Произвольный ID не заменяет подпись. Подпись старше часа отклоняется: закрой
Mini App и открой заново из Telegram. Токен бота во фронтенд не передаётся.
Публикуй через HTTPS сервер приложения, а не каталог `data/`.

## Поведение архива

- Приёмник проверяет владельца и состояние бизнес-подключения. Собственные правки
  видны, но не создают уведомлений и непрочитанных событий.
- Изменения и удаления собеседника по умолчанию уведомляют только владельца.
  Выключение уведомлений не останавливает сбор. Сбой оставляет задание для повтора;
  получение уведомления не отмечает событие прочитанным.
- Прочтение сохраняется сервером. Открытие диалога не отмечает невидимые события;
  есть отдельное действие «Прочитать всё».
- Фото сохраняется после ответа владельца, если Telegram передал доступный полный
  файл. Обычное входящее фото без ответа постоянно не скачивается. Ответ другого
  участника сохранение не запускает; неизвестный режим не называют одноразовым.
- Скачивание проверяет непустой файл и известные размеры передачи. Лимит — 20 MiB;
  до трёх автоматических попыток, затем повтор из Mini App. Недоступный файл
  и ошибка скачивания не показываются как успешное сохранение.
- Сбор зависит от запущенного приёмника и сети. Не полученные ботом события
  и уже исчезнувшие до получения файлы не восстанавливаются.

## Хранение и очистка

SQLite-база находится в `data/archive.sqlite3`, фото и аватары — рядом с ней.
Обычные сообщения хранятся как фоновые копии 30 дней от получения копии;
срок проверяется при открытии архива и в цикле приёмника. События, связанные
полученные версии и выбранные фото остаются до ручного удаления.
Сырые обновления Telegram и вложенные JSON-копии постоянно не ведутся.

Старая база экспериментального приёмника переносится при открытии автоматически:
исходное время получения сохраняется, исторические уведомления не отправляются.
Остаются фото по ответу владельца; ранее скачанные обычные медиа, не относящиеся
к этому сценарию, удаляются при переносе. Не запускай старый и новый приёмник
одновременно с одной базой.

Удаление записи, очистка диалога и всего архива требуют подтверждения в Mini App
и не меняют оригинальную переписку. Настройки сохраняются, неотправленные
уведомления отменяются. Новые события могут появиться, если сбор включён.
«Не сохранять этот диалог» останавливает поступления, оставляя старый архив.
Текущая находка: ручная очистка убирает данные из API, но ещё требует исправления
очистки активного SQLite WAL. До результата в [приёмке](../../.scratch/telegram-archive/acceptance.md)
физическое удаление всех активных копий не считается завершённым.

Каталог и локальные файлы ограничены правами владельца ОС. Прикладного шифрования
базы и фото нет: защита диска зависит от настроек Mac. Доставленные сообщения
бота, резервные копии и снимки файловой системы — отдельные копии; очистка архива
сама их не удаляет. При восстановлении базы срок фоновых данных проверяется снова.
`.env` и стандартный `data/` исключены из Git; свой каталог данных размещай вне
отслеживаемых файлов репозитория.

## Проверки

Из каталога `tools/telegram-media-probe`:

```sh
python3 -m unittest discover -s tests -p 'test_*.py' -v
```

Тесты используют временные каталоги и синтетические данные. Браузерные сценарии
`tests/mini_app.browser.js` и `tests/mini_app_states.browser.js` — функции
`async (page)` для Playwright/MCP, статический сервер `127.0.0.1:8794` и подставной
HTTP API. Точный объём и результаты общей приёмки записаны
[отдельно](../../.scratch/telegram-archive/acceptance.md).

Автоматическое сохранение самоуничтожающихся фото без ответа владельца остаётся
отдельным исследованием. В прежнем живом опыте одно фото было получено через ответ,
другой ответ содержал только метаданные. Это не доказывает автоматическую поддержку
временных фото, видео или других медиа. Подставной API и SDK не заменяют проверку
на реальном Telegram-клиенте с настроенным HTTPS-адресом.
