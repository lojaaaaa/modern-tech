# Тексты интерфейса и короткие сообщения

Основание: [SPEC.md](SPEC.md), [дизайн](DESIGN.md) и
[14 материалов о ясном тексте](research/writing-and-ai-text.md).
Тексты ниже — проектная редакция, не цитаты из источников.

## Голос продукта

Спокойный, прямой, без фамильярности и рекламной похвалы. Человек должен
понять состояние, действие и последствие. Обращение обычно не нужно;
метка собственных действий — «Вы», как согласовано в спецификации.

Служебный текст краткий, но сохраняет существенный смысл. «Очистить?»
слишком мало, если человек не знает объём удаления. Длинное нужное пояснение
лучше пустого короткого статуса. Основание: [Microsoft style](https://learn.microsoft.com/en-us/style-guide/top-10-tips-style-voice),
[Google clear language for global audiences](https://developers.google.com/style/translation).

**Редактируется наша служебная речь, а не чужая переписка.** Сохранённые
сообщения, имена и версии не «улучшаются», не переводятся и не пересказываются
ради лаконичности. Предпросмотр может иметь многоточие; полный текст доступен
в записи/истории. Для `Было / Стало` сравниваются исходные состояния.

## Как редактировать строку

1. Определить её работу: объект, состояние, действие, причина или последствие.
2. Назвать это обычными словами, поставить главное в начало.
3. Убрать повтор заголовка, пустую вводную и самооценку продукта.
4. Проверить факт: могло ли приложение достоверно узнать написанное?
5. Сохранить нужное ограничение и следующий шаг, если такой шаг существует.
6. Прочитать вслух и посмотреть в настоящей ширине экрана.

Это редакционный процесс, не детектор ИИ. «Кроме того», тире, пассивный залог
и списки допустимы, когда выполняют работу. Не добавлять искусственные
опечатки, сленг или случайный ритм ради «человечности».

## Словарь действий

| Название | Смысл |
| --- | --- |
| Архив | Диалоги с событиями и сохранёнными фото |
| История сообщения | Полученные состояния одного сообщения |
| Прочитать всё | Отметить текущие события этого диалога прочитанными |
| Уведомления | Доставка изменений и удалений в личный чат с ботом |
| Не сохранять этот диалог | Остановить дальнейший сбор, оставить накопленный архив |
| Очистить диалог | Удалить архивные данные выбранного диалога |
| Очистить архив | Удалить архивные данные всех диалогов |
| Удалить запись | Удалить выбранную запись и принадлежащие ей данные |

Одна операция сохраняет название в меню, подтверждении и результате.
«Очистить», «Не сохранять» и «Выключить уведомления» не являются синонимами.
Основание: [Google о согласованности](https://developers.google.com/style/translation),
[GOV.UK о подписях кнопок](https://design-system.service.gov.uk/components/button/).

## Готовые формулировки

| Ситуация | Основной текст | Пояснение / действие |
| --- | --- | --- |
| Поиск | Поиск по имени или @username | Доступное имя поля: «Поиск диалогов» |
| Нет совпадений | Ничего не найдено | «Проверьте имя или ник.» / «Сбросить поиск» |
| Архив ещё пуст | Архив пока пуст | «Здесь появятся изменения, удаления и сохранённые фото из подключённых диалогов.» |
| История загружается | Загружаем историю | Пояснение не требуется, если ожидание короткое |
| Не загружен список | Не удалось загрузить диалоги | «Повторить» |
| Изменение | Сообщение изменено | Метки «Было» и «Стало» |
| Нет прежней версии | Предыдущая версия не получена | Не подменять её текущим текстом |
| Удаление | Сообщение удалено | Автор исходного сообщения показывается отдельно |
| Нет удалённого содержимого | Содержимое не сохранилось | Причину назвать только если она известна |
| Удалено обычное медиа | Фото удалено / Видео удалено / Файл удалён | Доступная подпись, без выдуманной копии |
| Фото получает файл | Получаем фото | Не показывать непроверенный процент |
| Полное фото сохранено | Фото сохранено | Открыть изображение |
| В ответе нет доступного файла | Файл недоступен | «Бот не получил файл этого фото.» |
| Неудачная попытка скачивания | Не удалось сохранить фото | «Повторить», если повтор действительно реализован |
| Скопирован username | Ник скопирован | Краткий неблокирующий статус |
| Уведомления диалога выключены | Уведомления выключены | «Новые события продолжают сохраняться.» |
| Сбор диалога остановлен | Сохранение диалога выключено | «Новые события не добавляются. Старый архив остаётся.» |
| Удалена запись | Запись удалена | Не утверждать успех до завершения операции |
| Диалог очищен | Архив диалога очищен | «Новые события продолжат сохраняться», если сбор включён |
| Подтверждена потеря подключения | Нет подключения | Время последнего успешного получения данных |

Для статуса «Сбор работает» одного открытого Mini App недостаточно: нужен
фактический сигнал приёмника. Если свежесть состояния неизвестна, показывается
последняя известная проверка, а не вымышленное «Всё под контролем».

При исходной неопределённости пассивный залог точнее: «Сообщение удалено»
не утверждает, кто его удалил. Предпочтение активного залога не оправдывает
придумывание действующего лица. Основание: [GOV.UK clear language](https://guidance.publishing.service.gov.uk/writing-to-gov-uk-standards/writing-guidelines/clear-language/).

## Подтверждения удаления

| Объём | Заголовок | Текст | Кнопки |
| --- | --- | --- | --- |
| Запись | Удалить запись? | «Запись и принадлежащие ей данные будут удалены из архива. Переписка в Telegram останется.» | Удалить запись / Отмена |
| Диалог | Очистить архив диалога? | «События, фото и фоновые копии этого диалога будут удалены. Переписка в Telegram останется.» | Очистить диалог / Отмена |
| Весь архив | Очистить весь архив? | «События, фото и фоновые копии всех диалогов будут удалены. Переписка в Telegram останется.» | Очистить архив / Отмена |

Если сбор включён, добавить одну строку: «Новые события продолжат сохраняться».
Не скрывать это существенное последствие в малозаметной ссылке.
Текст связан с подтверждаемой операцией; копирование ника не нуждается
в таком же диалоге. Основание: [Apple Alerts](https://developer.apple.com/design/human-interface-guidelines/alerts).

## Шаблоны уведомлений

Примеры используют вымышленные данные. Имена — отдельное поле, без
автоматического склонения неизвестного username. Исходные сообщения не редактируются.

```text
Сообщение изменено
Анна · 14:32

Было: Встречаемся в 18:00
Стало: Встречаемся в 19:00
```

```text
Сообщение удалено
Анна · 14:35

Встречаемся в 19:00
```

Имя во втором примере означает автора исходного сообщения, не доказанного
инициатора удаления. Переход в приложение называется «Открыть диалог».
Разбиение длинного уведомления на части сохраняет порядок и полный текст
в архиве. Технические ID и названия API остаются в диагностике, а не
обязательной частью каждого пользовательского сообщения.

## Редактура шаблонной подачи

Это примеры плохой подачи и наших замен, не признаки доказанного AI-авторства:

| Раздутая или неточная фраза | Проектная редакция |
| --- | --- |
| «Ваш умный помощник бережно сохранил важный момент» | «Фото сохранено» — только после получения полного файла |
| «Произошла непредвиденная ошибка выполнения операции» | «Не удалось сохранить фото» |
| «Вы уверены, что хотите выполнить данное действие?» | «Очистить архив диалога?» и его последствия |
| «Всё сохранено, ничего не потеряется» | Статус конкретного файла или события |
| «Собеседник никогда не узнает» | «Бот не отправляет собеседнику сообщение о сохранении» |
| «Не просто история, а полный контроль над перепиской» | «История сообщения» |
| «Информация о важных обновлениях» | «Уведомления» |

Стоп-слово — повод проверить смысл, не команда удалить его всегда.
«Общие настройки» уместны при настоящем различии общих и диалоговых настроек.
Основание: [Бирман о словах интерфейса](https://bureau.ru/bb/soviet/20161220/),
[русская практика редактуры](https://bureau.ru/soviet/20220109/).

## Локализация и крайние случаи

- Числа имеют русские формы: 1 событие, 2 события, 5 событий, 11 событий,
  21 событие. Не собирать фразу фиксированным окончанием.
- Длинные имена/ники переносятся или сокращаются только в предпросмотре;
  доступное имя и детали сохраняют полный вариант.
- Дата и время должны отличать время исходного сообщения от времени правки.
  Не показывать время получения ботом как время действия без подписи.
- Ошибка, пустота, отсутствие файла и отсутствие разрешения — разные причины;
  короткая строка не должна их смешивать.

## Как кратко сообщать о работе над приложением

Это редакционные ориентиры для наших сообщений пользователю, не жёсткий
универсальный лимит длины:

1. Начать с результата или существенного ограничения.
2. Назвать проверку, если она влияет на доверие к результату.
3. Указать следующий шаг только если он действительно нужен.

Обычному обновлению достаточно 2–4 предложений. Одно число не требует
подзаголовка и таблицы. При риске потери данных краткость уступает
необходимому объяснению. Без пустой похвалы, повторения вопроса, отчёта
о каждом внутреннем действии и предложения снова подтвердить уже согласованное.

Пример: «Добавлен поиск по имени и нику с опечатками. Проверены похожие имена
и точные совпадения. Интерфейс пока использует тестовые данные».
Последнюю фразу можно писать только если это фактическое состояние.

## Проверка перед выпуском

Проверить все пользовательские строки по назначению, истинности, терминологии,
контексту и последствиям; затем на реальной ширине и с длинным содержимым.
Количество символов и оценка детектора ИИ не заменяют эту проверку.
В исследованиях LLM-письма изучались другие языки/жанры и конкретные модели:
[границы выводов T12–T14](research/writing-and-ai-text.md).
